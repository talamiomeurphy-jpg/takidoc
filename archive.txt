🏛️ ARCHITECTURE CIBLE PROPOSÉE (Hybride et Progressive)
L'objectif est de sécuriser et d'ajouter des fonctionnalités (Paiement, DOCX, PDF robuste) sans réécrire le frontend existant.
Schéma des flux :
Frontend (Existant) : L'utilisateur personnalise le document. L'aperçu est géré en temps réel par le navigateur.
Demande de génération :
Si le document est gratuit : Le frontend continue d'utiliser editor-pagination.js (html2canvas) pour économiser les ressources serveur.
Si le document est payant : Le frontend envoie une demande au Backend TakiDoc pour initier le paiement.
Backend TakiDoc (Nouveau microservice Node.js) :
Reçoit la demande de paiement.
Crée une entrée pending dans la table orders de Supabase.
Renvoie l'URL de paiement au Frontend.
Écoute les Webhooks d'OpenPay. Vérifie la signature cryptographique, le montant et l'ID de commande. Si valide, met à jour orders en paid.
Déblocage et Génération :
Le frontend interroge Supabase pour vérifier le statut paid.
Si payé, le frontend peut soit :
a) Télécharger via le moteur client existant (si la qualité suffit).
b) (Recommandé pour le DOCX et PDF haute fidélité) Demander au Backend TakiDoc de générer le fichier via un moteur headless (Playwright pour PDF, bibliothèque docx npm pour Word), qui renvoie un lien de téléchargement temporaire signé (Signed URL de Supabase Storage).

Coût maîtrisé : On n'utilise le serveur que pour ce qui est critique (vérification de paiement, génération DOCX complexe). Le PDF simple reste côté client si possible.

Évolutivité : Le microservice Node.js peut être hébergé sur Render (Plan Starter à 7$/mois pour éviter le "cold start") ou Railway, et peut monter en charge indépendamment du frontend.

Paiement (Futur) :
Au lieu d'utiliser un serveur Node.js sur Render (qui serait en veille et raterait les webhooks), nous utiliserons les Supabase Edge Functions (Deno).
Les Edge Functions sont intégrées à Supabase, ne subissent pas de "cold start" aussi pénalisants que Render pour les webhooks, et disposent d'un niveau gratuit généreux.
Flux : Frontend appelle l'Edge Function → Crée pending_purchases → Retourne l'URL OpenPay → OpenPay envoie le webhook à l'Edge Function → L'Edge Function vérifie la signature cryptographique et met à jour purchases en completed.
Génération DOCX (Futur) : Si le client-side est insuffisant pour le DOCX, l'Edge Function peut générer le fichier, l'uploader temporairement dans Supabase Storage, et renvoyer une URL signée (valide 24h) au frontend pour le téléchargement.

Coût : 0€ pour le frontend (Render Free), 0€ pour la base de données (Supabase Free Tier), 0€ pour la logique serveur (Supabase Edge Functions Free Tier).
Fiabilité : Les webhooks de paiement sont traités par une fonction serverless toujours disponible, éliminant le risque de perte de transaction dû à la mise en veille de Render.
Préservation : Aucune réécriture du frontend existant. Nous ajoutons simplement des points d'extension.

/* Pied de page TakiDoc (protégé) — version « globale » utilisée par les brouillons */
function isBrandElement(el) {
  if (!el || !PROTECT_BRAND) return false;

  const text = (el.textContent || '')
    .replace(/\s+/g, ' ')
    .trim();

  return (
    BRAND_TEXTS.some(b => text.includes(b)) ||
    el.matches('[data-takidoc-brand], .takidoc-brand, #takidoc-brand')
  );
}

/* Version « locale » : ne regarde que le texte PROPRE de l'élément,
   pour ne pas protéger tout un bloc qui contiendrait le pied de page */
function ownText(el) {
  return [...el.childNodes]
    .filter(n => n.nodeType === 3)
    .map(n => n.nodeValue)
    .join(' ')
    .replace(/\s+/g, ' ');
}

function isBrandNode(el) {
  if (!PROTECT_BRAND || !el || el.nodeType !== 1) return false;

  if (el.matches('[data-takidoc-brand], .takidoc-brand, #takidoc-brand')) {
    return true;
  }

  const text = ownText(el);
  return BRAND_TEXTS.some(b => text.includes(b));
}

async function loadTemplate(id) {
  if (!id) {
    throw new Error('Identifiant de document manquant dans l’URL.');
  }

  if (!supabase) {
    throw new Error(
      'Supabase ne s’est pas chargé. Vérifie les scripts dans editor.html.'
    );
  }

  const { data, error } = await supabase
    .from('templates')
    .select(`
      id,
      name,
      description,
      price_xaf,
      category_id,
      has_photo,
      has_color_picker,
      html_structure,
      css_styles,
      template_fields (
        field_name,
        field_label,
        field_type,
        default_value,
        is_required,
        display_order
      )
    `)
    .eq('id', id)
    .eq('is_active', true)
    .single();

  if (error) {
    console.error('Erreur Supabase lors du chargement du modèle :', error);
    throw new Error(`Impossible de charger le modèle : ${error.message}`);
  }

  if (!data) {
    throw new Error('Ce modèle est introuvable ou inactif.');
  }

  state.template = {
    id: data.id,
    name: data.name,
    description: data.description,
    price: data.price_xaf,
    category: data.category_id,
    hasPhoto: Boolean(data.has_photo),
    hasColorPicker: Boolean(data.has_color_picker),
    html: data.html_structure || '',
    css: data.css_styles || '',
    fields: (data.template_fields || [])
      .sort((a, b) => (a.display_order || 0) - (b.display_order || 0))
      .map(field => ({
        name: field.field_name,
        label: field.field_label,
        type: field.field_type,
        defaultValue: field.default_value ?? '',
        required: Boolean(field.is_required)
      }))
  };

  state.originalCss = state.template.css;
  state.draftKey = `takidoc_draft_${data.id}`;

  return state.template;
}

function splitSelectors(selectorText) {
  const result = [];
  let current = '';
  let depth = 0;
  let quote = '';

  for (const char of selectorText) {
    if (quote) {
      current += char;
      if (char === quote) quote = '';
      continue;
    }

    if (char === '"' || char === "'") {
      quote = char;
      current += char;
      continue;
    }

    if (char === '(' || char === '[') depth++;
    if (char === ')' || char === ']') depth--;

    if (char === ',' && depth === 0) {
      if (current.trim()) result.push(current.trim());
      current = '';
    } else {
      current += char;
    }
  }

  if (current.trim()) result.push(current.trim());
  return result;
}

function scopeSelector(selector) {
  const root = '#document-canvas';
  selector = selector.trim();

  if (/^(html|body|:root)(?=$|[\s.#:[>+~])/i.test(selector)) {
    selector = selector.replace(/^(html|body|:root)\b/i, root);

    return selector.replace(
      /#document-canvas\s+#document-canvas/g,
      root
    );
  }

  if (selector === '*') return `${root} *`;
  if (selector.startsWith(root)) return selector;

  return `${root} ${selector}`;
}

🔍 Analyse des erreurs
L'erreur Env name cannot start with SUPABASE_ :
C'est une bonne nouvelle ! Supabase bloque volontairement la définition manuelle de variables commençant par SUPABASE_.
Pourquoi ? Parce que Supabase injecte **automatiquement et de manière sécuriséeSUPABASE_URL et SUPABASE_SERVICE_ROLE_KEY dans toutes les Edge Functions. Vous n'avez rien à faire pour cela, c'est déjà configuré.
L'erreur 401 Non autorisé / Missing authorization header :
La passerelle (gateway) de Supabase bloque la requête avant même qu'elle n'atteigne votre code Deno, car elle ne sait pas à quel projet elle appartient.
La solution : Il faut ajouter l'en-tête apikey (qui est votre SUPABASE_ANON_KEY) dans la requête. Cela identifie le projet sans exiger que l'utilisateur soit connecté.

🏰 LA NOUVELLE STRATÉGIE "FORTERESSE" (Architecture définitive)
Pour respecter le coût zéro (Render Gratuit) tout en ayant une génération serveur sécurisée, nous allons mettre en place une architecture en 3 tiers :
Le Frontend (editor.js) : Il ne génère plus de fichier. Il rassemble les données modifiées (texte, couleur, photo en base64) et envoie une demande de génération.
Le Gardien (Supabase Edge Function authorize-download) :
Vérifie si le template est gratuit (price_xaf === 0) OU payant.
Si payant et SIMULATION_MODE = true : il valide automatiquement.
Si payant et SIMULATION_MODE = false : il vérifie le vrai statut de paiement.
Si autorisé, il génère un jeton sécurisé à usage unique (valide 5 minutes) et le renvoie au frontend.
Le Générateur (Microservice Node.js sur Render) :
Reçoit le jeton + les données du document + le format demandé (pdf ou docx).
Vérifie la validité du jeton auprès de l'Edge Function.
Utilise Puppeteer (pour un PDF pixel-perfect) ou la bibliothèque docx (pour un vrai fichier Word éditable).
Renvoie le fichier directement en flux (stream) au navigateur pour le téléchargement, sans rien stocker durablement.
